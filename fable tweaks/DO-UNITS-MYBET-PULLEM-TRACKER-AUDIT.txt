## PART 1 — UNIT-BASED STAKING: how many units per multi

Ben's numbers: **bankroll $1,500, 1 unit = $15** (1% of bankroll — the standard
unit convention). The engine already computes capped fractional Kelly
(`build/staking.py`: 0.25x Kelly, 5% per-bet cap, 15% per-round cap,
PROP_KELLY_MULTIPLIER 0.5). This part converts that into a **units
recommendation shown next to every multi**, using well-known staking rules:

1. **Config** (`config.py`):
   - `BANKROLL = 1500.0` (replaces/aliases DEFAULT_BANKROLL as the live value)
   - `UNIT_SIZE = 15.0`          # 1% of bankroll
   - `UNIT_STEP = 0.25`          # stakes rounded to nearest quarter-unit
   - `UNIT_MAX = 3.0`            # never more than 3u (4.5% roll) on one multi
   - `UNIT_MAX_LONGSHOT = 1.0`   # cap at 1u when combined odds >= 5.0
   - `PROMO_FLAT_UNITS = 0.5`    # flat stake for promo-only plays (Ben confirmed)

2. **`recommend_units(joint_prob, book_odds, promo_ev=None)` in `build/staking.py`:**
   - Positive edge (market-shrunk prob × book odds > 1): units =
     `fractional_kelly_fraction(prob, odds) * BANKROLL / UNIT_SIZE`,
     rounded DOWN to UNIT_STEP, clipped to [UNIT_STEP, UNIT_MAX]
     (UNIT_MAX_LONGSHOT when odds >= 5.0 — Kelly is noisiest on longshots).
   - No/negative edge but positive promo EV → `PROMO_FLAT_UNITS`, tag `PROMO ONLY`.
   - No edge, no promo → 0 units, tag `NO BET`.
   - No book price at all → `-` and tag `MODEL-ONLY (no price, no stake)`.
     Never recommend units off model-only fair odds.
   - Per-round governor: if the round's total recommended units exceed
     `KELLY_PER_ROUND_CAP * BANKROLL / UNIT_SIZE` (= 15u), scale all
     Kelly-derived stakes down proportionally (promo flats don't scale, they're
     already minimal). Reuse `stake_bets`'s existing scaling, don't duplicate it.

3. **Display.** Report ladder + cross-game multis get `Units` and `$` columns.
   Dashboard ladder tables show the same, plus a round-total exposure line
   ("Round total: 6.75u / $101.25 of 15u cap"). The tracker's stake field
   pre-fills with the recommendation ($ value).

4. **Tests:** kelly→units conversion, rounding, both caps, promo flat, NO BET on
   negative edge, model-only never staked, round governor scaling.

**Acceptance:** regenerated R17 shows a Units column on every ladder; every rung
has one of [Nu | 0.5u PROMO ONLY | NO BET | MODEL-ONLY]; round total ≤ 15u.

## PART 3 — POINTSBET PULL 'EM SGM (dedicated promo multi)

**Verified mechanics (PointsBet support pages, July 2026):** Pull 'Em is a token
applied AT BET PLACEMENT on a Same Game Multi (AFL supported). During the game,
BEFORE THE SECOND HALF STARTS, you may remove ONE eligible leg. The odds are
recalculated down by the removed leg's value and you confirm the new price.
It is NOT a refund — it's a free mid-game option to drop the worst leg.

Build one dedicated **PULL 'EM SGM per game**, designed so the option is worth
the most:

1. **Composition rule (`build_pull_em_sgm` in `build/multi.py` or report.py):**
   - Exactly **4 legs** (pulling one must leave a real 3-leg multi).
   - **3 anchor legs: disposals only**, p ≥ 0.70, three different players.
     Disposals accrue steadily → at half-time you can SEE who's off the pace,
     which is exactly when the pull decision happens. That's why anchors must
     be disposals, not goals (goals are lumpy and unreadable at HT).
   - **1 booster leg — the designated pull candidate**: higher disposal line or
     1+ goals, model p between 0.45 and 0.65, clearly marked "PULL CANDIDATE".
   - Target combined fair odds ~$3.00–$6.00. Respect the existing book-menu
     filter, one-leg-per-player, ≤1 tackles/marks cap, LEG_PROB_MAX.
2. **EV with the pull option, priced off the sim's per-iteration masks:**
   - Base EV as usual (joint prob × book odds − 1, market-shrunk when priced).
   - Option value: over sim iterations, take the cases where EXACTLY ONE leg
     misses and the other three hit. In those cases pulling the missing leg at
     HT would have saved the bet at reduced odds. Recovered value per iteration
     ≈ stake × (reduced odds of remaining 3 legs) − stake, where reduced odds =
     book combined odds ÷ the pulled leg's book price (or fair price if
     unpriced, labelled). Multiply by `PULL_DETECTION_PROB = 0.7` — a DOCUMENTED
     ASSUMED PRIOR (not fitted — no data exists) for "the failing leg was
     already visibly behind at HT". Show `Total EV = base + pull option EV`
     with the option's contribution printed separately, never silently merged.
   - Config knobs: `PULL_DETECTION_PROB = 0.7`, `PULL_EM_N_LEGS = 4`,
     `PULL_EM_ANCHOR_MIN_P = 0.70`, all commented as priors.
3. **Prices.** There is no PointsBet scraper — do NOT build one in this pass.
   Emit the pull-em legs into a `reports/<year>_r<N>_pointsbet_odds.json`
   template (same null-value convention as the existing odds template). With no
   prices: show fair odds, mark MODEL-ONLY, and per Part 1 recommend no stake.
   With prices filled in: full EV + Part 1 units (promo flat 0.5u if −EV,
   since the option still has value; Kelly units if genuinely +EV).
4. **The pull decision rule, printed under each PULL 'EM SGM:**
   "At half-time: each disposals leg needs ~50% of its line. Pull the leg
   furthest below that pace (or an injured/subbed player, pull immediately).
   If every leg is on pace, pull nothing — the token expires with the bet live."
5. **Report + dashboard:** new "PointsBet Pull 'Em" block per game, after the
   SGM ladder; same lock/track flow as other multis so it can be bet-tracked
   (ledger `ladder: "pull_em"`, `book: "pointsbet"`).
6. **Tests:** composition (4 legs, 3 disposal anchors ≥0.70, booster band,
   distinct players), option-EV math on a constructed mask set (exactly-one-miss
   cases valued, zero-and-two-miss cases not), template emission, model-only
   never staked.

**Acceptance:** R17 report shows a Pull 'Em SGM for every game with base EV,
option EV, total EV, the pull rule text, and a pointsbet odds template file.
